# Changelog

## 1.7.1 - undoable quarantine, settings that save, config checks, backups, CI

- `config.json` is checked when it is read. A value of the wrong type (`"port": "7333"`, `"roots": "D:\\Models"`) stops startup with the key name and the type it should be; a key the app does not know is a warning in the log, not a failure; a relative path (`"quarantine": "_quarantine"`) is resolved against the data folder. A UTF-8 byte order mark at the start of the file, which PowerShell 5's `Set-Content -Encoding UTF8` writes, is stripped with a warning instead of crashing the service as it did in 1.7.0.
- `GET /healthz` answers `{ok, version, dbOk}` with 200 when the database answers a `SELECT 1` and 503 when it does not, for a service monitor. A nightly backup writes `library-YYYY-MM-DD.db` (a `VACUUM INTO` snapshot, safe while the server runs) and a copy of `config.json` into `backups/` under the data folder at 03:00 local time, and once at startup when today has none; the newest 7 are kept. `backupDir` in `config.json` moves the folder; it never defaults to the library share.

## 1.7.0 - lighter pages, a scan that says what went wrong, actions that fail safely

- Every JSON response of 8 KB or more is gzipped when the browser accepts it (every browser does), and the file list no longer carries each file's full description: it is cut at 400 characters and the detail panel fetches the whole text from the new `GET /api/row?id=` route. On a 10,000-file library the first load went from several megabytes to a few hundred kilobytes. Duplicate groups are now sent as ids (`{kind, key, count, wasted, ids}`) and the page resolves them from the rows it already has, instead of receiving every duplicate row a second time.
- A scan that finishes with problems now says so on the page: files that could not be read are counted, and a library folder whose prune was skipped because it was unreachable is named, with the note that its rows were kept. Before, both only reached the service log.
- Preview rename, apply rename, History undo and quarantine catch a server error and show its message in the toast instead of leaving the page half-updated. Every toast that printed a raw `e.message` now unwraps the server's `{error}` body, so an HTTP 500 reads as the reason, not "Unexpected token".
- The scan stats files 16 at a time and writes its index rows in transactions of 500 instead of one autocommit per file, and `renames(new_path)` has an index, so History undo and the "already renamed" check stop doing table scans. Sending a file to the Recycle Bin runs PowerShell asynchronously; the server no longer freezes for the duration of the call.
- New tests in `test/sprint3.test.mjs` cover each of these (9 tests, 4 of them against the real server on a throwaway folder). The archive test cleanup now works on Linux too.

## 1.6.1 - nothing moves over another file, network drives, cross-site requests

- Delete on a network drive (a mapped drive such as X: or a `\\server\share` path) now moves the file to the quarantine folder instead. Windows has no Recycle Bin for network locations, so "send to the Recycle Bin" there was a permanent delete. The Delete confirmation says so when any selected file is on a network drive, and the result says how many files went to quarantine. If the app can't ask Windows which drives are network drives, it quarantines rather than guess. The Excel import's Delete column follows the same rule.
- Every move now checks its destination first. Batch rename apply records an error for a file whose new name already exists, instead of replacing it (a case-only rename is still allowed). Batch rename, single rename and History undo refuse a protected destination name, the same as a protected source. Tidying empty folders after a move never removes a protected folder such as `_templates` or `tool/_protected_backups`, even an empty one.
- Every POST must now be sent as `application/json` (the Excel import as `application/octet-stream`), and a request whose Origin is another site is refused with 403. Another web page open in the same browser can no longer send the app a delete request. If you reach the Explorer through a proxy that changes the Host header, list the page's origin in `allowedOrigins` in config.json.
- New tests in `test/sprint2.test.mjs` cover each of these; 9 of the 12 failed against 1.6.0 (the other 3 test the new helper modules directly).

## 1.6.0 - safety fixes

- Protected files now have a built-in floor that config.json cannot remove: `u1_template*.3mf`, `filament_types.3mf`, anything under a `_templates` folder and anything under `tool/_protected_backups`. The service log warns when the configured list is empty, and Settings asks before a save that stops protecting an entry.
- Batch rename no longer accepts a plan from the page. Apply sends the same `{ids, pattern}` or `{ids, titles}` it previewed; the server rebuilds the plan from the index and refuses any entry that leaves the file's folder, lands outside a library folder, touches a protected name, or changed since the preview. Failures now list the file and the reason.
- A rescan no longer drops index rows for a library folder that is missing or that had read errors during the walk (for example the NAS going offline mid-scan). Those rows, with their first-seen dates, stay until a clean rescan; the log says `skipped prune for <folder>: N errors`.
- Automatic archiving is now off by default (it was on, including for any config.json without an `autoArchive` key). When turned on, it waits until one run by hand from Settings, where the "N files qualify" count is shown and the run refuses if that count changed. Print history from U1 Print Hub is matched by absolute path (the Hub's models folder from its config.json, resolved through realpath so a mapped drive and its share agree), and Settings reports how many of the Hub's printed files match.
- New route-level tests run the real server on a throwaway folder with an empty protected list and post protected files to every route that moves, renames or deletes (Delete, quarantine, single rename, batch rename, undo, archive, restore, archive run, Excel import). Each must refuse and leave the file untouched. All of them failed against 1.5.0. `EXPLORER_DATA` points the server's data folder elsewhere for these tests.
- `package-lock.json` now carries the app's real version (it still said 1.0.1). Regenerated with `npm install --package-lock-only`; no dependency changed.
